Integrate with Any Custom Application

GeoLive is API-first infrastructure: integrate location ingestion and authorized reads into your own website, mobile app, dashboard, custom software, or backend without adopting GeoLive's management dashboard as your customer-facing interface. The separate GeoLive dashboard is optional for project setup and administration. For the current Cloudflare runtime, mobile and browser clients use a trusted backend relay; long-lived credentials must never be embedded in browser JavaScript, APKs, or app bundles. Database provisioning and production Workers are operator-managed.

This is developer infrastructure, not a consumer location-sharing application. Client applications must decide when location is collected and provide their own lawful and accurate permission and consent flows.

Release and Deployment Status

Code documentation describes a Cloudflare-native runtime and a separate maintained Node/PostgreSQL reference runtime. Cloudflare feature-parity and public customer onboarding must be verified before a production service-level or feature-availability promise.

Do not mix the Cloudflare and PostgreSQL/Redis runtimes against one production dataset. Available integrations, plans and processing locations are confirmed during onboarding, not assumed from a repository checklist.

Location Data and Privacy

Depending on the customer integration, location data may be precise and sensitive. Required controls include limited collection, authorization, retention, user access/deletion workflows, safe handling of keys, and clear customer responsibilities. A dedicated commercial privacy/data-processing agreement is required before customer production data is onboarded.
